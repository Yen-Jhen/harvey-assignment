02 / WHAT IS AN AGENT?

什麼是 AI Agent？

Agent 以目標為導向，根據任務與可用資訊判斷下一步，必要時使用工具，再回報或接受回饋。

理解目標

辨識使用者想完成的任務，以及資訊與權限是否足夠。

選擇行動

在允許的範圍內讀取資料或使用工具，形成結果。

回饋與調整

交給使用者檢查；有新資訊時再調整下一步。

Agent 不一定需要完全自主；是否能採取行動，取決於環境、工具和授權。

03 / SYSTEM

Harvey 的系統架構

Harvey 是提供持續背景與規則的工作空間；Agent 使用語言模型和可用工具協助研究者。

使用者與審核

提出任務、提供回饋、批准需要授權的操作，並做最終判斷。

Agent 與工具

讀取相關資料、理解限制、提出回答或建議；工具能力依環境與授權而定。

記憶與工作規則

保存背景、偏好、專案狀態與任務流程，供 Agent 按需讀取。

工作空間的定位

這不是自行訓練的模型，也不是已部署的全自動多 Agent 系統。

04 / LLM WIKI

LLM Wiki 如何累積知識？

來源與摘錄

逐份討論並確認範圍，保留可追溯的原文摘錄及來源摘要；摘錄明確標示並非完整原文。

互相連結的主題

將新資料融入已有主題，補上來源與相關條目，而不是只累積彼此孤立的摘要。

索引與日誌

索引幫助找到內容；追加日誌記錄每次 ingest、修改與來源。

規則與瀏覽

維護規則定義隱私與檢查步驟；Markdown 支持維護，離線 HTML 提供瀏覽入口。

目前整理 6 份 Harvey 文件；它們不是 6 份彼此獨立的科學研究。

05 / MEMORY & TRUST

記憶是背景，不是保證正確

按需讀取

以 Markdown 和版本歷史保存背景；根據當前任務選讀相關資料，而不是預設載入全部內容。

核對時效

舊筆記可能過時或互相衝突；應指出差異並核對可存取的現行資料，不自行猜測。

區分資訊性質

使用者的當前決定、可核對資料、歷史摘要與 AI 推論，各有不同性質。

標明不確定性

推論是推論，不應冒充測量或已驗證的結論；引用數值時應保留來源。

06 / PERMISSIONS

讀取、修改與執行：不同權限

只讀檢查

在有權讀取且範圍明確時，查看程式並指出可能問題；不等於批准修改。

修改程式

先提出要改的檔案、內容與原因，取得使用者明確批准後再處理。

執行分析

需要明確要求；程式邏輯檢查或修改批准本身都不等於科學結果已驗證。

詢問可行性不等於批准；這是文件所述的工作規則，不代表存在自動強制機制。

07 / LOOP & GRAPH

Agent 如何決定下一步？

回饋：有新資訊或需要修正 → 返回資料檢查。

批准：需修改正式研究程式 → 提出具體修改並等待批准；未批准則不修改。

結束或交回：回答完成，或需要使用者處理時，結束本次回應。

執行分析需另有明確授權。此圖是依工作規則整理的概念圖，不是已部署或自動強制的 graph 程式。

08 / EXAMPLE PROMPT

示意：一次唯讀請求

請說明研究助理在什麼情況下可以讀取背景、提出修改建議，以及何時需要我的批准。這次不要修改檔案或執行分析。

輸入

一個問題、任務範圍與本次不執行操作的限制。

可用工具與背景

在有讀取權限時查閱相關工作規則；以實際環境支援的方式讀取資料。

預期輸出

區分唯讀、具體修改的批准與分析執行的授權；不應自行修改或執行。

這是教學用的假設範例，不是實際執行紀錄，也不表示 Agent 行為已經通過測試。

09 / RESEARCH VALIDATION

建議不等於科學驗證

  1. 釐清研究目標、假設、輸入與預期結果；資訊不足時標明不確定性。
  2. 以唯讀方式檢視，區分已知事實、可能問題與具體建議。
  3. 提出具有獨立預期結果的簡化測試或解析極限，並記錄數值來源。
  4. 取得必要授權；由使用者執行或明確授權執行，並檢查與解讀結果。

這些是建議的流程，不代表本展示已執行科學分析或證明研究結論。

10 / REVIEW & HANDOFF

交接與獨立審查

文件交接

精簡記錄目標、假設、限制、審查與使用者決定。Git 保存版本，不會自動共享對話或啟動 Agent。

一般審查

可以參考其他意見與先前討論；有助於比較，但不應稱為盲審。

盲審的條件

第一輪只提供受限資料，記錄後才分享先前結論。不能確認隔離時，標示為一般審查並說明原因。

獨立驗證

從假設重新推導並檢查量綱、極限等；多模型意見一致仍不是獨立物理證據。

不同檔案不自動保證資訊隔離；交接文件也不能取代實際檢查。

12 / TAKEAWAYS

重點整理

保存與連結

讓背景與來源可追溯，並把不同來源的知識整合到相關主題。

使用者掌握決定

讀取、修改及執行需分別看待；使用者批准必要操作並負責最終判斷。

證據勝過一致

模型意見或交接紀錄不能取代獨立檢查與科學驗證。

按需求改善

以具體問題與驗收標準驅動小範圍改善，再由使用者評估結果。
